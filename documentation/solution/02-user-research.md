# User research bundle

**Status, stated first:** no primary user research has been done yet. What follows are **proto-personas and hypotheses** drawn from the published needs of each group and from the questions comparable registers answer (see international-comparators.md). Each must be tested with real users before being treated as findings.

## Proto-personas

| Who | Question they bring | What they need from us | Hypothesis to test |
|---|---|---|---|
| Journalist or investigator | Who is responsible for this body, and who funds or owns it? | A chain with sources they can cite, today | Wants the evidence trail more than the visual |
| Researcher or academic | How has the state changed, and what does it cost? | Stable identifiers, dated editions, bulk downloads, method | Values the concordance and trends more than search |
| Public servant (policy, data, finance) | Which bodies are in scope for this policy, return or review? | A reference list to reuse, joined to the codes their systems use | Will use the feed and CSVs, rarely the page |
| Civil society, campaigner | Who can I hold to account, and through which elected body? | Plain language and a clear route to the elected body | Needs answers by name search, on a phone |
| Developer or data reuser | Can I build on this safely? | Feed contract, open standards, licence, change log | Will judge it on BODS validity and stability |
| Contributor | How do I fix something that's wrong? | A short form, a visible review, credit | Will only contribute if a fix shows up quickly |

## Journeys (hypothesised)

1. **Answer a question:** search a name → profile → chain with sources → download or cite.
2. **Explore the state:** start at an elected body → drill down the hierarchy → filter by type, nation or function → compare.
3. **Follow the money:** body → funding, running costs, PFI charges → owners and investors.
4. **Reuse:** data page → choose a format → read the contract → subscribe to changes.
5. **Contribute:** spot an error → correction form with source → public review → fix published with credit.

## Research plan

| Method | With whom | Question | Effort |
|---|---|---|---|
| Five-person usability test per persona, remote, on a phone and desktop | Recruited through the GitHub discussion and open data communities | Can they get from a name to an evidenced answer unaided? | About 2 days per round |
| Unmoderated first-click test | Anyone, via a public link | Does the question-led navigation route people to the right place? | Half a day |
| Contributor diary | First ten contributors | What stops a correction being made? | An hour a week |
| Accessibility test with assistive-technology users | Disabled users, paid for their time if a budget exists | Can every journey be done with a screen reader and keyboard? | 1–2 days |
